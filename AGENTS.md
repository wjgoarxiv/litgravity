# AGENTS.md — LitGravity

LitGravity is the LitFamily package for Google's Antigravity CLI (`agy`). This repo is independent: its own git history, npm package `@litfamily/litgravity`, version and tests. It shares ideas with its siblings and no files; re-express any family feature in agy's own plugin idiom.

## Layout

- `plugin/` — the agy plugin that gets installed. `plugin/plugin.json` is the manifest. `plugin/hooks.json` sits at the plugin ROOT (agy never reads `hooks/hooks.json`). `plugin/hooks/*.mjs` are the hook scripts and `plugin/hooks/lib/` holds the shared code (routes, re-entry, transcript reader, policy, prose guards, continuation holds). `plugin/rules/AGENTS.md` is the always-on contract. `plugin/agents/*.md` are subagents. `plugin/skills/<id>/` are the skills. `plugin/hud/statusline.mjs` is the opt-in status line script and `plugin/hud/render.mjs` builds its line. `plugin/lib/python-pick.mjs` picks the Python the engine runtimes build their environment from.
- `lib/` + `bin/litgravity.mjs` — the dependency-free installer, doctor, list, models, runtime and uninstall.
- `test/` — `node --test`; `test/fixtures/fake-agy.mjs` stands in for the host so tests never touch the real `~/.gemini`. Transcript fixtures are in `test/fixtures/transcripts/`.
- `scripts/` — version lockstep, legacy-token scan, `validate-plugin.mjs` (wraps `agy plugin validate`), `sync-fixtures.mjs` (re-pins `skill-depth.json` and `pack-files.json`) and `qa-cover-recipes.mjs` (the motion cover QA; needs Chrome, libwebp and a warm motion runtime, so it is not part of `npm test`).

## Gates

```bash
npm test
npm run check:version
npm run scan:legacy-tokens
npm run validate                              # agy plugin validate --json --strict: 0 errors, 0 warnings (free, offline)
npm pack --dry-run --json --ignore-scripts    # read [0].files; test/fixtures/pack-files.json pins it
npm run sync:fixtures                         # after skills or package files change; read the diff
npx litgravity list                           # every skill with its route words and engine
```

The real-render motion tests skip unless a warm motion runtime exists (`LITGRAVITY_MOTION_RUNTIME=<dir>` or the default cache; fill one with `node plugin/skills/lit-typographic-motion/scripts/motion-runtime.mjs install --json`). Run them, and the cover QA (`node scripts/qa-cover-recipes.mjs --negatives`; the painted recipe relights its pinned five-panel base `test/fixtures/motion/painted-light-base.png`, never the seven-panel README picture), after any change under `lit-typographic-motion`, at `nice -n 10` and one render at a time. A fresh-clone check (copy the tracked-to-be set to a temp folder and run `npm test` there) proves nothing pinned depends on untracked state.

## Host facts (probed on agy 1.4.3, 2026-10-20; re-probe on a new build)

- **hooks.json shape is strict.** `{ "<name>": { "<Event>": [...] } }`. SessionStart, PreInvocation, PostInvocation and Stop take a FLAT list of handlers; PreToolUse and PostToolUse take `{matcher, hooks:[...]}` groups. One wrong group makes agy skip the whole file while `/hooks` still lists it, so `test/hooks.test.mjs` asserts the shape and `agy plugin validate --json --strict` must report nothing. Handlers run with the plugin folder as cwd, so commands are `node ./hooks/<name>.mjs`.
- **No `UserPromptSubmit`.** The prompt is not in the hook payload. Bare `lit` is `PreInvocation` with `invocationNum` 0: read the newest `USER_INPUT` step from `transcriptPath` (its `<USER_REQUEST>` block) and answer `injectSteps`. It fires for every turn, including resumed conversations. `SessionStart` fires once per new conversation, never on resume.
- **Hook payloads are camelCase** (`conversationId`, `workspacePaths`, `transcriptPath`, `toolCall: {name, args}`, `terminationReason`). Tool names differ between builds and surfaces. A headless run of 1.4.3 called `read_file` (`Path`), `write_file` (`Path`, `Content`, `Overwrite`), `run_command` (`CommandLine`, `WaitMsBeforeAsync`), `invoke_subagent` (`TypeName`, `Prompt`, `Role`, `Model`) and `ask_question` (`questions[]`); older conversations used `view_file`, `write_to_file`, `replace_file_content`, `multi_replace_file_content`, `list_dir`, `grep_search`, `find_by_name`. The hook payload names a tool by its step type, which this repo has not captured for file tools, so write detection is by name pattern or by path plus content arguments, never by one fixed name.
- **PreToolUse cannot abstain.** Every answer needs a `decision` (`allow`, `deny`, `ask`, `force_ask`, `deny_unless_prior_grant`). An empty object `{}` is read as a denial with an empty reason: on 1.4.3 it blocked `read_file`, `write_file`, `run_command` and `ask_question` of a whole lit-plan turn (live run, 2026-10-20). `ask` prompts the user (soft-denied in print mode) and `allow` may lift the user's own approval prompts (probe run2 suggests it does not override the print-mode denial of `run_command`; interactive behavior is UNCONFIRMED). So `hooks.json` keeps the PreToolUse matcher on `invoke_subagent|define_subagent`, which never prompt, and file writes, shell commands and prose are checked after the fact by `lib/boundary.mjs` (a workspace snapshot at the start of the lit turn, compared in PostInvocation and Stop). `hooks/pre-tool-use.mjs` still carries the full policy; widening the matcher to `.*` turns it on, but only after someone proves in an interactive session that `allow` leaves the approval prompt in place.
- **Headless `-p` auto-denies `run_command` and `write_file`** unless agy was started in a permissive mode, with `permissions.allow` rules or with `--dangerously-skip-permissions`. The denial ends the run: `response` is empty, the JSON lists `denied_actions`, stderr says `jetski: no output produced`. `read_file` inside the workspace is allowed. A plugin that is a symlink to a folder OUTSIDE the workspace was denied its skill `read_file` (W2 probe, 2026-10-20); a project-scope copy inside the workspace was read. User scope (`~/.gemini/config/plugins`) was not probed headless (the build rule keeps `~/.gemini` read-only), so UNCONFIRMED. The router's activation note therefore tells the model to read first and to report BLOCKED with the permission it needs.
- **Live proofs on 1.4.3 (2026-10-20, 12 model calls in all):** bare `lit` ignites (`LIT IGNITED · lit-loop`, then one question); after `lit plan …` a resumed bare `lit` (`agy -p … --conversation <id>`) was routed as a continue (the hook ledger says `"how":"continue"`), though that reply was empty because a write was denied; with lit-loop active a resumed bare `lit` answered `LIT CONTINUES · lit-loop` without reading the skill again; `lit new` ignites again; `lit brainstorm …` makes the model read `skills/lit-brainstorm/SKILL.md`; `PostInvocation`, `PostToolUse` and `Stop` fire (`LITGRAVITY_HOOK_TRACE=<file>` logs one line per hook call: SessionStart once, PreInvocation and PostInvocation per invocation, Stop with `NO_TOOL_CALL`); **the model reads a PNG through `read_file`** (it answered a word nobody had typed). The PostToolUse payload carries `toolCall` and `error` but no command output. A resumed conversation keeps the workspace and plugin copy it started in, whatever the current folder is.
- **Still UNCONFIRMED:** interactive `allow` from PreToolUse, status-line stdin fields, child agents spawned for real (`lit-team`, reviewer lanes), `browser_subagent` and `generate_image` argument shapes, `command_status`, whether user-scope skill files are readable headless.
- **A SKILL.md loads only its first 24,000 bytes** (the validator warns above that). Rules files are capped at 24,000 bytes too. Depth beyond the cap goes into `references/`, which is why the depth fixture also pins the folder's file count and total bytes.
- **Starter Quota.** The user's account has a small model quota. Real `agy -p` calls are rationed (a build uses at most 15 in total); everything else uses `agy plugin validate --json` and `agy -p "/hooks"`, `"/skills"`, `"/agents"`, which cost nothing.
- Plugin names share one global namespace and the first one found wins silently, so doctor warns when both scopes hold a copy.
- The status line is user-level only (`~/.gemini/antigravity-cli/settings.json`, key `statusLine`; `ANTIGRAVITY_GEMINI_DIR` does not move it, so a live stdin capture needs the user's own settings). The installer touches it only with `--status-line`, backs the file up first, and refuses a status line it did not write unless `--replace-status-line` is given, which saves the old value to `$XDG_DATA_HOME/litgravity/backups/statusline-replaced.json` for `uninstall` to restore. agy disables a status line after repeated failures, so `hud/statusline.mjs` always exits 0. Only `model.display_name` (read as `Gemini 3.8 Flash (Medium)`) and `context_window` (`used_percentage`, and a `context_window_size` that rounds to 1049k) were seen live, through the predecessor line on 2026-10-21; `quota`, `cost`, `vcs`, `agent_state`, `task_count` and `conversation_title` are read defensively from the binary's field names and the changelog, and their shapes are UNCONFIRMED.

## Gotchas

- **Route state is outside the workspace** (`$XDG_STATE_HOME/litgravity/sessions/<workspace hash>/<conversationId>.json` plus a `.journal`), so a planning-turn tool call cannot lift its own limit. PreToolUse denies writes there on every route.
- **The boundary scan is bounded**: `lib/boundary.mjs` walks at most 20,000 files or 1.5 s per call (PreInvocation snapshot, then each PostInvocation and Stop), skips `.git`, `node_modules`, `.agents`, `.litgravity`, build output and caches, keeps up to 200 small prose files in memory, and marks the snapshot `partial` past the limits (a partial snapshot reports no deletions). It runs only while a lit route is active, never in plain conversations.
- **Do not name sibling products or their tools** anywhere under `plugin/`. `test/depth.test.mjs` fails on sibling product names, host names and the tool names of other hosts, and `npm run scan:legacy-tokens` repeats part of that.
- **Skill folders must not contain `evidence/`, `plans/` or `.litgravity/` directories**: `.gitignore` ignores them and the pack test fails.
- **Work from this repo's own root.** Another agent's hooks may write their state folder into whatever directory a shell sits in; `.gitignore` keeps every `.lit*/` folder out of the repo, and the pack allowlist keeps it out of the package.
- Engines (`office`, `diagram`, `readme`, `sciviz`, `motion`) ship as `<name>-runtime.mjs` in `plugin/lib/` or a skill's `scripts/` (`office` lives in `lit-pptx` and also serves `lit-docx`), answer `status|install --json` with `{name, ready, cache, missing}`, and install only into `$XDG_DATA_HOME/litgravity/runtime/<name>`. `litgravity runtime` and doctor find them by file name; `lib/list.mjs` maps the engines a skill uses but does not own (`SHARED_ENGINES`).
- **Python 3.15 has no wheels** for the pinned packages. The engines that build a Python environment call `plugin/lib/python-pick.mjs` (a `python3` newer than 3.14 falls through `python3.14` to `python3.10`; the engine's `LITGRAVITY_*_PYTHON` variable always wins; no fit is `BLOCKED` with the fix). `doctor` shows the pick as `python for engines`.
- **Motion hooks.** `plugin/hooks/lib/motion.mjs` holds the done gate (arm on activation, record in PostToolUse, evaluate in Stop through `engine/node/done.mjs`). State sits beside the route state as `<conversation>.motion.json`. Hooks run through `run()` in `lib/common.mjs`, which accepts a promise because the done-check is loaded lazily.
- **Motion cover QA contract.** Every negative and regression declares `mustFail` (`G2.floor`, `G1.target`); the QA calls a case caught only when the render finished and was gated (exit 0 or 13, a manifest), every declared gate failed at its tier, and no undeclared FLOOR gate failed. Do not retune a threshold, and do not declare `G4` for `feather-150`: its seamLocal wanders 1.91 to 2.01 around the 2.0 TARGET. Recipe rows were re-pinned for the LITGRAVITY brand word (weight-tide median d 0.01022, orbit-loop at 88 px, bytes 1 558 982 and 1 348 480).
- **Depth fixtures name each exemption.** `closureExempt`, `hostNameExempt` and `illustrativeRefs` list single files, each with a reason in `exemptionReasons`, and `test/depth.test.mjs` scans every byte of every bundle file (text, binaries, the XML inside docx and pptx) for sibling product names. Vendored third-party files stay verbatim and hash-pinned.
- Bump versions only with the user's approval, in `package.json`, `plugin/plugin.json` and `CHANGELOG.md` together.
- No publish, tag or push without explicit approval. Re-check Google's brand terms for "Antigravity" before the first publish.
- Local state stays untracked: `.litgravity/` and other `.lit*/` folders, `HANDOFF.md`, `evidence/`, `plans/`.

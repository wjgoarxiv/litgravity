# Final wave, review gate and completion

## Final verification rows

After the last implementation row is ticked, the plan's `F1` to `F4` rows remain. They run against the final state of the tree, with fresh artifacts and fresh commands. Tick them one at a time, each when its verification passed with evidence, using the same one-line edit as for ordinary rows.

- **F1, plan compliance audit.** Every row and acceptance criterion is met. A `lit-verifier` pass reads the plan, the goal record and the evidence folder and returns PASS or FAIL per criterion. Rerun every QA scenario from gate D against the final state.
- **F2, quality and diagnostics.** The complete test suite with no skip flags, no `.only` and no new expected-failure markers. Typecheck, lint and build. `node --check` on scripts. `agy plugin validate plugin --json --strict` for a plugin bundle. The repository's legacy-token or forbidden-word scanner when prose changed. The pack listing read through `npm pack --dry-run --json --ignore-scripts` (`[0].files`) when packaging was touched. `quality-reviewer` reads the whole diff for defects and idiom.
- **F3, real manual QA.** Each criterion's scenario runs again on the final tree through its named channel, with evidence saved as `final-<criterion>.<ext>` and a cleanup receipt.
- **F4, scope fidelity.** `git diff --name-only` against the union of the Files lines shows nothing extra and nothing from Must NOT have. No version bump, tag, publish, push or commit happened without approval. The dirty paths from Bootstrap are still dirty for the same reason and were not rewritten by tooling.
- **F5, release and readiness** (applies when docs, manifests, command surfaces, hooks, scanner logic or package assets changed). Every changed file maps to a row. Digests and generated payload pins were regenerated by their documented command. The scanners and the pack listing ran. Any dead code removed was first proven unused by search or test evidence and appears in a receipt.

### Ledger integrity check

Read the ledger end to end. Every ticked row has an `evidence` entry whose files exist. Every entry carries a non-empty cleanup receipt. Every acceptance line has an artifact on disk. Close any gap before the next step.

## Global review gate

Before any completion claim, read `../review-work/SKILL.md` and run it in work mode against the final diff, with the plan as the intent and the evidence folder, the run command and the verification evidence as inputs. Its goal lane covers F1 and F4, its quality lane F2 and its qa lane F3. The security and context lanes add coverage the plan did not ask for. All five lanes must return PASS. A timeout, a missing deliverable, an acknowledgement-only child, an explicit `BLOCKED:` or an unfinished lane stops the completion claim.

Pair the review with a hypothesis audit even when the review passes. Name at least three plausible failure hypotheses for the changed surface, run the distinguishing check for each against the actual artifact and append the ruled-out or confirmed result to the ledger. When a lane or a hypothesis fails, read `../debugging/SKILL.md`, confirm the root cause with runtime evidence, add the minimal failing test or reproduction, fix it, rerun the affected verification and rerun the gate.

## Completion steps

1. `node "<skill-folder>/../lit-plan/scripts/check-plan.mjs" --complete plans/<slug>.md` prints `PLAN_COMPLETE_PASS` once every row is ticked and the structure holds.
2. Close the goal record by the `litgoal` rules: `done` only when every criterion is `pass` with evidence on disk. When a host goal tool was used for this run, update it too.
3. Remove the run's worktrees, scratch files and processes and verify their absence. Write `cleanup.md` and a ledger `note` with the receipt.
4. Write the internal receipt (shape in `execution-templates.md`) to `.litgravity/evidence/<slug>/final-receipt.md`.
5. Stop before commit, push, tag, version bump or publish. State plainly which of those happened (none, unless the user granted them). When the conversation stops at a checkpoint instead of completing, leave a handoff with `lit-handoff`.

## Evidence layout

| Artifact | Path under `.litgravity/evidence/<slug>/` |
| --- | --- |
| Pin facts and baseline | `pin.txt`, `baseline.log` |
| Row packet | `task-N-packet.md` |
| Per row | `task-N-pin.log`, `task-N-red.log`, `task-N-green.log`, `task-N-accept.<ext>` |
| Claim and verdict | `task-N-doneclaim.json`, `task-N-verify.md` |
| Cleanup | a receipt line next to the artifact and a ledger `note` |
| Final wave | `final-<criterion>.<ext>`, `verification.log`, `final-receipt.md`, `cleanup.md` |
| Review gate | `review/` (written by `review-work`) |

Each log opens with the command and the working directory and ends with the exit status. Ledger lines: `decision` for approvals, tier, scope changes and defaults taken in headless runs; `evidence` per ticked row with its paths; `note` for the pin, baselines, receipts, pauses and blockers.

The receipt for a run (and for each slice when the run is long) holds: changed files grouped by surface; measured results with the command that measured them (a word count states its counting rule); verification commands with status and the decisive line; the surface probe and what it observed; adversarial classes with one-line outcomes (reasons for the not-applicable ones); the cleanup receipt; the release-neutral receipt; and remaining risks tied to a missing command or an unverified environment. A claim that the repository is globally clean requires a `git status` read, and a claim that all tests pass requires the full suite to have run. A failure is called pre-existing when a clean-base run fails the same way.

Evidence stays safe to share. Redact tokens, credentials, auth headers, cookies, API keys, environment dumps and personal data before writing logs, ledger lines or handoffs, and use lengths, hashes or short prefixes when identity matters.
